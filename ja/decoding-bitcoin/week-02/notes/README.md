## 重要な考え方

- **ウォレットが組み立て、ノードが検証する。** 創造的な仕事をするのはウォレットです。コインを選び、アウトプットを作り、署名します。ノードは確認するだけです。すべてのノードが、すべてのトランザクションを自分で検証します。最初は届いたとき、そしてブロックに現れたときにもう一度です。

- **ノードはそれぞれ自分のメンプールを持つ。** メンプールは、まだブロックに入っていない有効なトランザクションを集めた、ノードごとのプライベートなリストです。ノードは、トランザクションを違うタイミングで知り、違う制限やポリシーを持ち、衝突するトランザクションを違う順序で見ることがあります。そのため、メンプールは互いに似てはいても、同じである保証はありません。合意されているのは、ブロックチェーンだけです。

- **承認は確率の話。** ブロックに入ったトランザクションは 1 承認です。そのブロックは、まだリオーグで取り除かれる可能性があります。その上にブロックがマイニングされるたびに、それはずっと難しくなります。支払いが数学的な意味で確定する瞬間はありません。リスクにさらされる金額に対して何承認で十分とするかは、受け取る人がそれぞれ決めます。

- **浅いリオーグはふつうに起こる。** 2 人のマイナーがほぼ同時にブロックを見つけると、ノードの見方が一時的に食い違います。次のブロックで決着がつき、負けたブロックのトランザクションはメンプールに戻ります。深いリオーグには大量のハッシュレートが必要で、それこそが、攻撃者が二重支払いをするために必要なものです。

- **アウトプットは全額が使われる。** UTXO の一部だけを使うことはできません。支払いは、コインをまるごと使い、新しいコインを作ります。支払い、自分に戻るおつりのアウトプット、そして残ったものが手数料です。

- **トランザクションは、部品の短いリスト。** バージョン、インプット、アウトプット、ロックタイム（segwit ではさらにマーカー、フラグ、witness）。送り主のフィールドも、手数料のフィールドも、インプットの金額もありません。インプットはアウトポイント（`txid:vout`）を名指しするだけで、残りはノードが自分の UTXO セットから引いてきます。

- **所有の証明は、スクリプトのチェック。** アウトプットを使うには、そのアウトプットのロックスクリプトを成功させるデータ（たいていは署名と公開鍵）を、インプットが提供しなければなりません。それに加えて、アウトポイントが未使用であること。ノードに必要なのはこれだけです。

## よくある勘違い

| 勘違い | 正しくは |
|---|---|
| 「メンプール」は、1 つのグローバルなリストだ。 | すべてのノードが自分のメンプールを持っています。mempool.space が表示しているのは、mempool.space のノードのメンプールです。 |
| 1 承認のトランザクションは確定している。 | リオーグで取り除かれることがあります。承認はリスクを下げますが、ゼロにはしません。 |
| 手数料は、トランザクションの中のフィールドだ。 | 手数料は、インプット引くアウトプットです。誰もそれを書き込みません。 |
| インプットには、使われる金額が入っている。 | インプットは、アウトポイントを名指しするだけです。金額は、前のトランザクションのアウトプットにあります。 |
| おつりは、同じアウトプットに戻る。 | 古いアウトプットは完全に使われます。おつりはまったく新しいアウトプットで、たいていは新しいアドレスに送られます。 |
| `sendrawtransaction` にはウォレットが必要だ。 | 署名済みのトランザクションをブロードキャストするのに、秘密の情報は必要ありません。どのノードでもリレーできます。 |

## ファシリテーターへのヒント

セッションの前に：

- 出力やエラーを把握しておけるよう、まっさらな regtest チェーンで自分でラボを実行しておきます。
- ウォークスルーをステップ 7 から始められるよう、エクササイズ・ドライバーのノードが動いていて、ステップ 1〜6 が済んでいることを確認します。
- mempool.space を開いておき、予測ブロックと、未承認から承認済みに変わるトランザクションを見せられるようにします。
- Reorg Calculator をハッシュレート 10% で試し、表示される数字をメモしておきます。ホワイトペーパーとは違う式を使っているかもしれないからです。

つまずきやすいところ：

- **"Fee estimation failed. Fallbackfee is disabled."** ノードに `-fallbackfee=0.0001` が必要です。これを付けて `bitcoind` を再起動します。
- **"Multiple wallets are loaded. Please select which wallet to use..."**（エラーコード -19。v29 より前は "Wallet file not specified" というメッセージでした）。ウォレットを 2 つ読み込んでいる場合、`-generate` も含めて、ウォレットのコマンドにはすべて `-rpcwallet=alice` か `-rpcwallet=bob` が必要です。
- **シェルのクォート。** `createrawtransaction` に渡す JSON は壊れやすいです。`echo "$INPUTS"` と `echo "$OUTPUTS"` を実行して、自分が何を組み立てたのかを確認してもらいましょう。金額は数値（クォートなし）、txid はクォート付きでなければなりません。
- **おつりの金額の間違い。** インプット引くアウトプットがマイナスの場合、署名はできますが、`testmempoolaccept` は金額についてのエラー（`bad-txns-in-belowout`）で失敗します。計算を確かめましょう。
- **未成熟のコインベースを選んでしまう。** `listunspent` には使えるコインしか表示されませんが、`getblock` から txid をコピーすると、使うのが早すぎるとして失敗します。`listunspent` を使いましょう。
- **メンプールはグローバルだと思い込む。** グループが興味を持ったら、発展課題 B（2 つのノード）が手軽でよいデモになります。

## 用語集

- **メンプール（mempool）：** ノードが持つ、有効で未承認のトランザクションの集合。
- **リレー（relay）：** トランザクションやブロックをピアに伝えること。
- **ポリシー（policy）：** 何を受け入れ、何をリレーするかについての、ノード独自のルール（最低手数料、標準的なスクリプト）。コンセンサスより厳しく、ノードによって違うことがあります。
- **コンセンサスルール（consensus rules）：** すべてのノードがブロックに適用しなければならないルール。破ると、ブロックは無効になります。
- **承認（confirmation）：** トランザクションが入ったブロックと、その上の N-1 個のブロックがチェーンにあるとき、そのトランザクションは N 承認です。
- **リオーグ（reorg、チェーンの再編成）：** よりワークの多い別のチェーンに乗り換えること。先端のブロックが切り離されます。
- **二重支払い（double spend）：** 同じコインを使う 2 つのトランザクション。承認されるのは片方だけです。
- **アウトポイント（outpoint）：** アウトプットへの参照：`txid:vout`。
- **おつりのアウトプット（change output）：** 余った金額を送り主に戻すアウトプット。
- **scriptPubKey（ロックスクリプト）：** アウトプットの中にある、それを使うために満たすべき条件。
- **scriptSig / witness（アンロックデータ）：** インプットの中にある、その条件を満たすデータ。
- **ロックタイム（locktime）：** トランザクションをブロックに入れられる、最も早いブロック高または時刻。
