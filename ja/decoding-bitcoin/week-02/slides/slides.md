# 支払いの一生

```
ウォレット（作成 + 署名）
  |
ノード --リレー--> ピア --> それぞれのメンプール
  |
マイナーが手数料率で選ぶ
  |
ブロック --> すべてのノードが再検証
  |
1 承認、2 承認、... 6 承認
```

- すべてのノードが、すべてを自分で検証する

<!--
図を上から下へたどる。聞く：検証はどこで起きている？（すべてのノードで、リレーのときと、ブロックの中でもう一度。）
創造的な仕事をするのはウォレットで、ノードは検証するだけだと指摘する。
-->

---

# メンプールはローカル

- 1 つのノードのメモリにある、有効で未承認のトランザクション
- すべてのノードが自分のメンプールを持つ
- 届く順序が違い、ポリシーも違う
- メンプールがいっぱい：手数料率が最も低いものを追い出す
- 共有されているのはブロックチェーンだけ

<!--
聞く：mempool.space を見ているとき、誰のメンプールを見ている？（彼らのノードのもの。）
maxmempool のデフォルトは 300 MB で、いっぱいになると mempoolminfee が上がることに触れる。
-->

---

# リオーグと承認

```
        +-- B3 -- B4          <- 負け（B3 の tx はメンプールへ）
B1 -- B2
        +-- B3' -- B4' -- B5' <- ワークが多いほうが勝つ
```

- ノードは、最もワークの多い有効なチェーンに従う
- 1 承認は取り消されることがある
- リスクはブロックごとに速く下がる（攻撃者が 50% 未満の場合）

<!--
自然な 1 ブロックのリオーグは、2 人のマイナーが同時にブロックを見つけたときに起こる。
Reorg Calculator、攻撃者 10%：1 承認で約 20%、3 承認で 1.3%、6 承認で 0.02%（ホワイトペーパーの式）。
-->

---

# コインはまるごと使われる

```
インプット
  50 BTC のコイン (txid:0)
アウトプット
  1 BTC           -> Bob
  48.99998590 BTC -> Alice（おつり）
手数料
  50 - 49.99998590 = 0.0000141 BTC
```

- アウトプットの一部だけを使うことはできない
- おつりを忘れたら？ 手数料になる

<!--
これは regtest ラボの実際の数字：141 vB × 10 sat/vB = 1410 sats。
聞く：手数料はトランザクションのどこに書かれている？ どこにもない。この先の週は、これを土台に進む。
-->

# トランザクションの部品

| 部品 | 役割 |
|---|---|
| バージョン | どのルールが適用されるか |
| インプット | どのコインを使うか、とアンロックデータ |
| アウトプット | 金額 + ロックスクリプト |
| （witness） | segwit インプットの署名 |
| ロックタイム | マイニングできる最も早い時点 |

- インプットは `txid:vout`（アウトポイント）を指す

<!--
概要レベルにとどめる。バイトレベルの細かい点は来週。
聞く：トランザクションに入って「いない」ものは？ 送り主、手数料のフィールド、インプットの金額。
-->

# ディスカッション問題

1. 一生：誰が組み立て、リレーし、検証し、承認する？
2. メンプールとは？ なぜ共有された 1 つのメンプールはない？
3. リオーグとは？ なぜもっと多くの承認を待つ？
4. なぜおつりは新しいアウトプットとして戻る？
5. トランザクションの主な部分を順番に
6. インプットは何を指す？ なぜそれで十分？

# 演習のウォークスルー：手作業のトランザクション

```bash
bitcoin-cli -regtest createrawtransaction "$INPUTS" "$OUTPUTS"
bitcoin-cli -regtest -rpcwallet=alice \
  signrawtransactionwithwallet "$RAW"
bitcoin-cli -regtest testmempoolaccept '["'$SIGNED'"]'
bitcoin-cli -regtest sendrawtransaction "$SIGNED"
bitcoin-cli -regtest getmempoolentry "$TXID"
```
