## 重要な考え方

- **二重支払い問題。** デジタルの情報は、タダでコピーできます。どんなデジタルキャッシュの仕組みでも、同じコインを 2 回使われないようにしなければなりません。ビットコイン以前に実際に機能していた答えは、唯一の台帳を管理する信頼された会社でした。ビットコインの答えは、誰でも確認できる共有の台帳です。そこでは、トランザクションの順序がプルーフ・オブ・ワークによって決まります。

- **プルーフ・オブ・ワークは、ボスなしで順序を決める。** マイナーは、結果がターゲットを下回るまで、ブロックヘッダーを繰り返しハッシュします。そのようなハッシュを見つけるのにはコストがかかりますが、確認するのは簡単です。ノードは、累積ワークが最も多い有効なチェーンに従います。履歴を書き換えるには、攻撃者はほかの全員よりも速くそのワークをやり直さなければなりません。

- **ハッシュ関数はあらゆるところにある。** ハッシュ関数は、どんな入力でも固定サイズの指紋に変えます。ビットコインは、ハッシュ関数が一方向であること、衝突耐性があること、そして入力のわずかな変化で無関係な出力になることを頼りにしています。ハッシュは、トランザクション（txid）とブロックに名前を付け、ブロックをチェーンにつなぎ、ブロックのマークルルートを作り、公開鍵を短くしてアドレスにします。

- **口座ではなくコイン。** ビットコインは残高を保存しません。保存するのは、未使用トランザクションアウトプット（UTXO）です。トランザクションは、UTXO をまるごとインプットとして使い、新しいアウトプットを作ります。受取人に送らなかった分は、おつりのアウトプットとして自分に戻り、それでも残った分は手数料としてマイナーのものになります。

- **残高はウォレットが計算する。** ウォレットは、自分の鍵でアンロックできる UTXO を見つけて合計します。ノードは、誰が何を持っているかを知りませんし、気にもしません。確認するのは、1 つひとつの支払いがルールに従っているかどうかだけです。

- **Don't trust, verify（信頼するな、検証せよ）。** フルノードは、すべてのブロックとトランザクションを自分で検証します。インストールするソフトウェア（リリースの署名、再現可能ビルド）や、自分の支払いも検証できます。それでも一部の信頼は残ります（暗号技術、ハードウェア、コードレビュー）。ただし、何を信頼するかは自分で選べます。

- **regtest は自分の実験室。** regtest は、ノートパソコン上のプライベートなチェーンです。ブロックを一瞬でマイニングでき、コインに価値はありません。Week 2 からは、これを使ってあらゆるアイデアを `bitcoin-cli` で試します。

## よくある勘違い

| 勘違い | 正しくは |
|---|---|
| 「ウォレットの中にビットコインが入っている。」 | コインは、ブロックチェーンに記録された UTXO です。ウォレットが持っているのは、それを使える鍵です。 |
| 「ビットコインは、銀行口座のように残高を保存している。」 | プロトコルの中に残高は存在しません。ウォレットが、自分の鍵でコントロールできる UTXO を合計しています。 |
| 「ハッシュは暗号化の一種だ。」 | 暗号化は、鍵があれば元に戻せます。ハッシュはまったく元に戻せません。できるのは、入力を推測して比べることだけです。 |
| 「コインの一部を使うと、残りは元のアウトプットに残る。」 | アウトプットは必ず全額が使われます。残りは新しいおつりのアウトプットに入ります。 |
| 「マイナーがルールを決める。」 | すべてのフルノードが、すべてのブロックを検証します。ルールを破ったマイナーが作ったブロックは、ノードに拒否されます。 |
| 「ビットコインは最初のデジタルキャッシュだ。」 | DigiCash などが先にありました。ビットコインは、信頼された中央の主体なしで機能した最初のものです。 |

## ファシリテーターへのヒント

セッションの前に：

- Discord のボイスチャンネル、画面共有、ダッシュボードが動くことを確認します。
- Hash Functions ツールと mempool.space を、ブラウザのタブで開いておきます。
- 最後に参加者が選べるよう、Week 2 の問題と役割の一覧を用意しておきます。
- セットアップの問題を手助けできるよう、まっさらなマシンに自分で Bitcoin Core をインストールしてみます（または、[`bitcoin_core_cli.md`](../exercises/bitcoin_core_cli.md) が最新リリースと合っていることを確認します）。

つまずきやすいところ：

- **セットアップ。** ソースからのビルドは時間がかかり、パッケージ不足で失敗します。ほとんどの人には、リリース版のバイナリ（ラボの方法 A）を勧めましょう。Bitcoin Core v29 以降を使ってもらうようにします。v29 以降のビルドは、`./configure` と `make` ではなく CMake を使います。
- **regtest で `sendtoaddress` が失敗する。** "Fee estimation failed" と表示されます。ノードに `-fallbackfee=0.0001` が必要です（または、コマンドに `fee_rate` を指定します）。
- **`getrawtransaction` が承認済みのトランザクションを見つけられない。** ノードを `-txindex=1` 付きで起動します。
- **残高についての混乱。** 101 ブロックをマイニングしたら 5050 BTC あるはずだと思う人が多いです。コインベースの成熟を説明する絶好の機会です。
- **発言の少ない参加者。** 多くの人は、第二言語で読んでいます。質問する前に考える時間を取り、名前を呼んでやさしく発言を促しましょう。テキストチャットでの回答も認めます。

## 用語集

- **二重支払い（double spend）：** 同じコインを、2 つの異なるトランザクションで使おうとすること。
- **プルーフ・オブ・ワーク（proof of work）：** たくさんのナンスを試して、ターゲットを下回るブロックヘッダーのハッシュを見つけること。行うのは難しく、確認するのは簡単です。
- **ハッシュ関数（hash function）：** 任意の入力を、元に戻せない固定サイズの出力に対応させる関数。ビットコインは主に SHA-256 を使います（SHA-256 を 2 回かけたものは hash256 と呼ばれます）。
- **雪崩効果（avalanche effect）：** 入力をほんの少し変えると、出力のビットの約半分が変わること。
- **UTXO：** 未使用トランザクションアウトプット。まだ使うことができるコイン。
- **UTXO セット：** すべてのフルノードが保持している、全 UTXO の一覧。
- **おつりのアウトプット（change output）：** 余った金額を送り主に戻すアウトプット。
- **手数料（fee）：** インプットの合計からアウトプットの合計を引いたもの。マイナーのものになります。
- **コインベーストランザクション（coinbase transaction）：** 各ブロックの最初のトランザクション。新しいコイン（補助金と手数料）を作り、マイナーに支払います。
- **コインベースの成熟（coinbase maturity）：** コインベースのアウトプットは、100 ブロック後にならないと使えません。
- **フルノード（full node）：** すべてのブロックとトランザクションをダウンロードし、ルールに照らして検証するソフトウェア。
- **regtest：** ブロックを一瞬でマイニングできる、ローカルのプライベートなテスト用チェーン。
